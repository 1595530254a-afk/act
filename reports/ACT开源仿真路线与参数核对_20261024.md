# ACT 开源仿真路线与参数核对

核对日期：2026-10-24（北京时间）。本次只查原作者、Hugging Face 与 Seeed 的公开文档和源码，另保存两份小型公开配置；没有安装软件、下载模型权重、启动训练、运行新策略或控制真机。

结论：确实有可复用的完整 ACT 仿真路线。建议先用 LeRobot 已发布的 ACT 权重和它配套的 gym-aloha 环境验证标准执行链，再回到 B601 做本体与场景适配。标准 ALOHA 基线验证的是 ACT 实现和执行流程；当前 B601 七通道 checkpoint 的好坏，仍需用匹配它的本体、图像与动作定义来测。

## 1. ACT 原作者路线：完整生成数据、训练、评估

仓库：[tonyzhaozh/act](https://github.com/tonyzhaozh/act)。本次核对 commit：`742c753c0d4a5d87076c8f69e5628c79a8cc5488`。

自带两个 MuJoCo / dm_control 任务：Transfer Cube（双臂传方块）和 Bimanual Insertion（双臂插接）。有脚本专家生成示范，随后训练 ACT，再由 ACT 输出关节目标进行物理闭环评估。脚本专家的成功与训练后策略的成功应分别记录。

| 原作者 Transfer Cube 示例参数 | 数值 |
|---|---:|
| 生成示范 | 50 episodes |
| 训练/验证划分 | 40 / 10 episodes |
| batch size | 8 |
| 学习率 | 1e-5 |
| num_epochs | 2000 |
| 实际优化器更新数 | 10,000 |
| chunk size | 100 |
| KL weight | 10 |
| hidden / feedforward | 512 / 3200 |
| 随机种子 | 0 |

关键计数：此仓库的 Dataset 长度等于 episode 数，每次访问一条 episode 时随机取其中一个动作块起点；不是一次 epoch 遍历整条轨迹的每一帧。40 条训练示范、batch 8，每轮只有 5 个训练 batch，代码执行 `range(num_epochs)`，所以 2000×5 = 10,000 次更新。不能把这里的 2000 epochs 当成 LeRobot 的 2000 steps，也不能按 40×400 帧计算该旧加载器的一轮长度。

训练每轮先离线验证再训练，保留最佳验证 checkpoint；每 100 epoch 存档。`--eval` 是独立评估入口，运行 50 次 rollout 并保存视频；`--temporal_agg` 是可选的重叠预测时间集成。最佳验证权重的更新次数不一定等于最终权重的 10,000 次。源码依据：[每轮训练](https://github.com/tonyzhaozh/act/blob/742c753c0d4a5d87076c8f69e5628c79a8cc5488/imitate_episodes.py#L339-L370)、[存档](https://github.com/tonyzhaozh/act/blob/742c753c0d4a5d87076c8f69e5628c79a8cc5488/imitate_episodes.py#L380-L390)。

原作者还明确提醒：loss 平台期之后，继续训练仍可能改善动作流畅性与成功率；实景建议至少 5000 epochs。这里同样是该旧代码的 epoch，不是对所有任务保证“5000步足够”。[原作者 README](https://github.com/tonyzhaozh/act/blob/742c753c0d4a5d87076c8f69e5628c79a8cc5488/README.md)、[数据加载源码](https://github.com/tonyzhaozh/act/blob/742c753c0d4a5d87076c8f69e5628c79a8cc5488/utils.py)、[训练评估源码](https://github.com/tonyzhaozh/act/blob/742c753c0d4a5d87076c8f69e5628c79a8cc5488/imitate_episodes.py)。

README 提供的是源码、示范与训练流程；本次未在该 README 找到直接下载其仿真训练 checkpoint 的入口。任务策略需要训练，视觉骨干使用 ImageNet 预训练，不应把它说成所有参数完全从零初始化。需要现成 ACT 仿真权重时，优先看下面 LeRobot 的正式发布。

模型卡说明发布权重来自 **80,000 步 checkpoint**，500 回合评估成功率为 **83%**。这些是发布者报告，本机尚未复现；任务成功指右臂抓起方块并交接到左臂，不是红块放进灰盒。不能与本项目 0/6 直接当成同一测试排名。[模型卡训练与评估说明](https://huggingface.co/lerobot/act_aloha_sim_transfer_cube_human#training-details)。

| 配置 | 数值 |
|---|---:|
| 数据 | 50 episodes / 20,000 帧 |
| batch size | 8 |
| 策略学习率 / 视觉骨干学习率 | 1e-5 / 1e-5 |
| 优化器 | AdamW |
| weight decay | 1e-4 |

| 配置里的计划训练预算 | 100,000 steps |
| 模型卡所述发布 checkpoint | 80,000 steps |

| temporal_ensemble_coeff | null，即未启用 |
| KL weight | 10 |
| seed | 1000 |
| 观测/执行频率 | 50 Hz |
| 单回合长度 | 400 步，即 8 秒 |
| 输入 | 一路顶部 RGB＋14 维关节/夹爪状态 |
| 输出 | 14 维双臂动作 |

配置里的训练预算与已发布权重所在步数是两回事。配置中的训练期间评估为每 20,000 步、50 回合；模型卡单独报告的最终大评估为 500 回合。评估并行 batch 与训练 batch 也不是同一个量。

该路线可以先直接加载发布权重评估，第一步无需重新训练。要检查自己的训练流程，再用相同任务数据和公开设置训练、逐 checkpoint 比较物理成功率。

兼容性仍需实际核验：模型卡标出的训练代码为 LeRobot `3c0a209f9fac4d2a57617e686a7f2a2309144ba2`，属于旧版接口；当前模型仓库配置也经历过格式转换。保存配置不是已经确认它能在本机 LeRobot 0.6.1 中直接运行。应使用独立环境核对权重、归一化、数据版本和 gym-aloha 依赖，不覆盖现有 B601 环境。[训练当时依赖说明](https://github.com/huggingface/lerobot/blob/3c0a209f9fac4d2a57617e686a7f2a2309144ba2/pyproject.toml)。

gym-aloha 当前源码快照为 `6203fac50be47065056b69094e44308972202258`；这只是本次检索到的版本，不证明它与发布者训练当年的环境版本相同。模型卡还指出不同实现对成功判定的细节可能影响结果，复现时要保留具体环境版本和评分规则。

## 3. Seeed 的 B601-RS 仿真能提供什么

本项目已使用的官方来源：[Seeed-Projects/reBot_RS_Sim](https://github.com/Seeed-Projects/reBot_RS_Sim)，commit `438f7713d83fb8cd0d0cb05e8cc335264dd3997a`。它提供 B601-RS 的模型、MuJoCo 接触仿真、腕部与顶部相机、IK/PD 控制以及 ROS2 接口。

核对到的抓放演示基于物体仿真状态、IK 和任务逻辑；不能仅凭它能抓放就称为 ACT 成功。ROS 的目标检测也明确从仿真物体状态生成。它适合提供本体与物理环境，在已核查版本中没有找到配套 ACT 权重、训练命令及随机位置评估基线。结论限于本次核对的仓库，不能扩展成“网上绝对没有 B601 ACT 仿真”。[官方 README](https://github.com/Seeed-Projects/reBot_RS_Sim/blob/438f7713d83fb8cd0d0cb05e8cc335264dd3997a/README.md)、[网页直接读取物体位置](https://github.com/Seeed-Projects/reBot_RS_Sim/blob/438f7713d83fb8cd0d0cb05e8cc335264dd3997a/web_mujoco/src/grasp-demo.js#L146-L151)。

任务服务里的 `record` 保存时间和六个关节角的 CSV，没有配套双相机、夹爪和 ACT 动作标签，不能当作完整的 LeRobot 训练数据导出。[记录实现](https://github.com/Seeed-Projects/reBot_RS_Sim/blob/438f7713d83fb8cd0d0cb05e8cc335264dd3997a/rebotarm_mujoco_rs/rebotarm_mujoco_rs/task_server.py#L586-L614)。

另外检查了 [reBot-Isaacsim README](https://github.com/Seeed-Projects/reBot-Isaacsim/blob/158f87317fcaa35a7d1706ef364e324d3565939e/README.md)，固定 commit `158f87317fcaa35a7d1706ef364e324d3565939e`：有 USD、UDP 同步、IK 与预设关节测试，在已查入口也未见完整 ACT 训练与 checkpoint。官方 [B601-RS LeRobot 教程](https://wiki.seeedstudio.com/rebot_arm_b601_rs_lerobot/#training-and-evaluation) 则确有真实示范采集、ACT 训练及加载权重到真机的流程，不能把这些真机命令当作 MuJoCo 评估命令。

Seeed 的真机 LeRobot 教程、机械臂仿真模型，与 ALOHA 的完整 ACT 基准是不同层面的资源，不能混成同一套已经验证通过的 B601 仿真方案。

## 4. 与本项目保留模型的差别

| 条件 | LeRobot 发布的 ALOHA 仿真模型 | 本项目保留的 B601 仿真适配 |
|---|---|---|
| 训练性质 | 该任务 ACT 训练，含 ImageNet 视觉骨干初始化 | 已训练的真实场景权重继续适配 |
| 当前相关训练数据 | 50 段人类仿真示范 | 25 个位置的合成成功示范 |
| batch size | 8 | 2 |
| 学习率 | 1e-5 | 3e-6 |
| 保留权重的本轮多位置训练 | 80,000 步 checkpoint | 新增 600 步 |
| 动作维数 | 14 | 7 |
| 图像 | 顶部一路 | 顶部、腕部两路 |
| 频率 | 50 Hz | 30 Hz |
| 每次执行动作数 | 100，约 2 秒 | 100，约 3.33 秒 |
| 任务 | 双臂交接 | 单臂抓取入盒 |

本项目 600 步、batch 2 相当于抽取 1200 个动作块起点样本，不是将全部示范完整遍历 600 遍；未来动作块可能互相重叠。不同分支的训练步数不能累加到最终保留权重上。

之前更长分支离线误差下降但闭环失败，说明离线 MAE 不能替代任务成功率；它不能证明“继续按标准流程训练没有意义”，也不足以证明 ACT 泛化普遍较差。当前数据、初始化、采样、频率、学习率和训练预算与标准基准同时存在差异。

此前本地每 10 步重查询一次的稀疏时间集成，也不等同于原作者 `--temporal_agg`：官方启用后每个 50 Hz 仿真步都预测新块，再加权合并重叠预测。本地那次结果不能当作原版时间集成已经被完整复现或否定。[官方频率](https://github.com/tonyzhaozh/act/blob/742c753c0d4a5d87076c8f69e5628c79a8cc5488/imitate_episodes.py#L191-L198)、[官方加权实现](https://github.com/tonyzhaozh/act/blob/742c753c0d4a5d87076c8f69e5628c79a8cc5488/imitate_episodes.py#L246-L261)。

本地依据：[保留模型训练记录](D:/外置大脑/ACT/runs/mujoco_iteration_20261023/multisite_v1/adapt_v1/training_report.json)、[本轮完整结果](D:/外置大脑/ACT/reports/ACT多位置适配迭代_20261023.md)。当前 B601 来源模型自身的模型卡报告 50 段真实数据、100,000 步、batch 16、学习率 1e-5，但未提供评估结果；这是来源训练，不能充当本轮新仿真数据已经充分训练的证据。[B601 来源模型卡](https://huggingface.co/nikodembartnik/act_rebot_cube)。

## 5. 建议的推进顺序与验收

1. **先验证公开完整基线。** 加载 LeRobot 的已训练 ACT 和配套 ALOHA 环境，先做少量链路检查，再做固定随机种子的独立多回合评估。保留实际模型 SHA、输入、预测动作、评分和全部失败视频。不要求第一次小样本恰好等于发布者的 83%。
2. **再验证训练复现。** 对齐数据、采样、batch、学习率和初始化；从同一分支保存连续训练曲线及多个 checkpoint，以验证集物理抓放选模型，最终测试位置另行留出。比较的是成功率随更新次数的变化，不只比较单笔 loss。
3. **最后回到 B601。** 使用其官方本体环境，核对七通道关节方向、单位、夹爪、两路相机和执行频率。复用标准 ACT 训练与评估流程，B601 数据和权重保持与本体匹配。ALOHA 的 14 通道权重不能直接替换 B601 的 7 通道 checkpoint。

这三步分别回答“标准 ACT 流程是否正常”“本机是否能复现学习”“当前 B601 策略是否完成目标”。不能把通过第一步写成第三步已经通过。

关于先仿真再真机：对在该仿真训练、又在同一物理定义下测试的候选，随机位置抓放持续失败，确实不应将其当成已经可用的部署模型。对真实数据训练、直接放进重建仿真的来源权重，失败还可能来自视觉和动力学差异，不能据此一票否决其真实场景能力。仿真通过同样不能代替实机的本体、标定与控制核对。
