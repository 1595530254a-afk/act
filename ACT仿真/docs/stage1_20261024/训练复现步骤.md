## 先选路线，避免在缺少起点时直接运行训练

|你要复现什么|需要什么|本文入口|
|---|---|---|
|用项目选定的权重重新评估|项目另行提供的 **step3000 六文件 checkpoint**、官方仿真资产、公开运行输入、两个环境|完成第 1～3 步，再走路线 A|
|从公开模型开始重新训练同类实验|固定版本的公开模型与数据，重新生成单点 teacher、训练新的 sim300、生成多位置 teacher 和 RGB，再连续训练 5000 步|完成第 1～3 步，再走路线 B|

Git 中包含源码、配置快照和最小运行输入模板，**不包含历史 sim300 权重，也不包含约 20 GiB 的多位置 RGB**，不包含两个 Python 环境或官方模型网格缓存。不能只 clone 仓库就声称完整训练数据已经齐备。

历史选定权重的来源是：公开 ACT → 原真实数据续训 1000 步 → 单位置 sim300 → 多位置新分支 step3000。这里的“新分支 step3000”是连续 5000 步分支的中间保存点，不是 sim300。历史真实数据续训 1000 的中间权重、历史 sim300 均不是 Git 自带文件。

路线 B 为了从可下载的起点开始，明确采用“公开 ACT → **新生成的单位置 300 步分支** → 新多位置 5000 步分支”。它与历史训练起点不同，单点阶段还明确采用 FP32，因此不能保证同一模型 SHA、同一最优 step，或复得原报告的 8/8。若要严格核对历史训练链，需要项目另行提供相应历史中间权重及其身份记录；不要拿最终 step3000 替代 sim300。

## 1．准备一个干净的项目工作副本和两个环境

下载或克隆仓库源码后，先进入仓库一级目录 **`ACT仿真/`**。本文后续所有“项目根”均指这个仿真子目录，不是 Git 仓库根；里面保留 `simulation/`、`scripts/`、`resources/`、`docs/` 的相对布局。下面所有命令使用同一个 PowerShell 窗口；工作副本可以在任意合适磁盘，代码不要求原作者电脑的绝对路径。

```powershell
# 在克隆后的 Git 仓库根执行；已经位于 ACT仿真 时跳过这一行。
Set-Location '.\ACT仿真'
$ActRoot = (Get-Location).Path
if (-not (Test-Path -LiteralPath 'simulation\adapt_act_multisite_20261024.py')) {
    throw '当前目录不是 ACT 项目根。'
}
$ActPython = Join-Path $ActRoot '.venv\Scripts\python.exe'
$SimPython = Join-Path $ActRoot 'local\mujoco-env\Scripts\python.exe'
```


ACT 环境用根目录的 `requirements.lock.txt`；其中 Torch 2.10.0+cu130、torchvision 0.25.0+cu130、LeRobot 0.6.1。仿真环境用 `simulation/requirements.lock.txt`，其中 MuJoCo 3.17.0。**不要把两个环境混装。** 此处 B601 评估会启动 `.venv` 内的 CUDA worker，训练脚本也要求 CUDA；CPU 能运行部分数据检查，但不能代替这里规定的训练与 CUDA 评估。

## 3．恢复公开运行输入到代码实际读取的位置

公开副本在 `docs/stage1_20261024/runtime_inputs`。严格按其中 `path_mapping.json` 的对应关系恢复；详细说明也见同目录上一级的 `public_reproduction.md`。本步只使用相机、场景、位置等第一阶段输入。

|公开文件|恢复目标，相对项目根|
|---|---|
|`source_protocol.json`|`runs/mujoco_validation_20261023/position_generalization_20261023/protocol.json`|
|`camera_fit.json`|`runs/mujoco_iteration_20261023/camera_fit/camera_fit.json`|
|`successful_reference_scene.xml`|`runs/mujoco_validation_20261023/fixed_flat40_20261023/policy_step300_progress_fix/scene/task_scene.xml`|
|`position_plan.json`|`runs/mujoco_iteration_20261024/position_plan.json`|

可以在干净工作副本中运行下面的内联恢复命令。它不新增恢复脚本、不覆盖已有目标；若目标已存在，先核对它是不是需要保留的历史文件，不要删除旧实验来强行通过。

```powershell
@'
import hashlib,json,pathlib
root=pathlib.Path.cwd().resolve()
public=root/'docs/stage1_20261024/runtime_inputs'
mapping=json.loads((public/'path_mapping.json').read_text(encoding='utf-8'))
wanted={'source_protocol.json','camera_fit.json','successful_reference_scene.xml','position_plan.json'}
entries=[e for e in mapping['entries'] if pathlib.Path(e['public_copy']).name in wanted]
targets=[root/e['restore_target_relative_to_ACT_ROOT'] for e in entries]
assert len(entries)==4 and not any(p.exists() for p in targets), '目标已存在或映射不完整，先核对'
escaped_root=json.dumps(str(root),ensure_ascii=False)[1:-1]
for e,target in zip(entries,targets,strict=True):
    source=root/e['public_copy']
    raw=source.read_bytes()
    assert hashlib.sha256(raw).hexdigest()==e['public_copy_sha256']
    target.parent.mkdir(parents=True,exist_ok=True)
    if source.suffix=='.json':
        data=json.loads(raw.decode('utf-8').replace('<ACT_ROOT>',escaped_root))
        target.write_text(json.dumps(data,ensure_ascii=False,indent=2)+'\n',encoding='utf-8')
    else:
        target.write_bytes(raw)
protocol=root/'runs/mujoco_validation_20261023/position_generalization_20261023/protocol.json'
data=json.loads(protocol.read_text(encoding='utf-8'))
for path_key,hash_key in [('camera_fit_path','camera_fit_sha256'),('successful_reference_scene','successful_reference_scene_sha256')]:
    data[hash_key]=hashlib.sha256(pathlib.Path(data[path_key]).read_bytes()).hexdigest()
protocol.write_text(json.dumps(data,ensure_ascii=False,indent=2)+'\n',encoding='utf-8')
for target in targets:
    print(hashlib.sha256(target.read_bytes()).hexdigest(),target)
'@ | & $ActPython -
if ($LASTEXITCODE -ne 0) { throw '运行输入恢复失败。' }
```

占位符替换和 JSON 重新保存会改变字节与 SHA。上面打印的是**本次恢复文件的新 SHA**，不能冒称原始冻结 SHA。参考 XML 恢复到表中的目录深度，以保留网格相对路径的含义。`camera_fit.json` 是为仿真重建的虚拟相机候选，不代表真实相机标定。

路线 A 与路线 B 都需要完成这一步。旧协议中记录的模型路径是历史来源说明；新评估实际模型由 `--model-dir` 指定。

### A1．放好六个模型文件并核对身份

项目需另行提供 checkpoint；目前没有可以从 Git 直接下载这个本地训练 checkpoint 的命令。把六文件放到项目根下的 `local/public_checkpoints/act_long5000_step3000`：

```powershell
$SelectedModel = Join-Path $ActRoot 'local\public_checkpoints\act_long5000_step3000'
$ModelFiles = @('config.json','model.safetensors','policy_preprocessor.json',
  'policy_postprocessor.json','policy_preprocessor_step_3_normalizer_processor.safetensors',
  'policy_postprocessor_step_0_unnormalizer_processor.safetensors')
foreach ($Name in $ModelFiles) {
    Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $SelectedModel $Name)
}
$ModelHash = (Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $SelectedModel 'model.safetensors')).Hash.ToLowerInvariant()
if ($ModelHash -ne 'c25ffa08fd2b67343f37eab06bb948642e2a6d2578e387a563ba81105c506c2c') {
    throw '这不是历史选定的 step3000 权重。'
}
```

另外五文件也必须与提供者的六文件清单一致，不能把其他模型的 processor 拼进来。权重主体约 197 MiB，超过普通 Git 单文件限制；Git 中的配置快照不等于完整模型。

### B2．从公开 Parquet 导出第 0 回合，给 teacher 提供起始轨迹

teacher 固定读取 `runs/mujoco_validation_20261023/inputs.npz`。完整历史 `export_inputs.py` CLI 还依赖未放入 Git 的旧本地 RGB fixture，因此这里只复用它公开的 `load_episode0()` 读取函数，原样导出本步骤真正需要的回合数据；不调用模型，也不伪造历史预测。

```powershell
@'
import sys,json,pathlib
sys.path.insert(0,'simulation')
from export_inputs import load_episode0
import numpy as np
root=pathlib.Path.cwd().resolve()
target=root/'runs/mujoco_validation_20261023/inputs.npz'
note=target.with_name('inputs_public_source.json')
assert not target.exists() and not note.exists(), '已有输入必须保留，先核对来源'
arrays,info,episode,sources=load_episode0(root/'data/rebot_cube')
assert episode['length']==403 and info['fps']==30
target.parent.mkdir(parents=True,exist_ok=True)
with target.open('xb') as stream:
    np.savez_compressed(stream,**arrays)
note.write_text(json.dumps({'schema':'minimal_public_episode0_for_teacher_v1',
    'frames':403,'fps':30,'source_files_sha256':sources,
    'model_forward_calls':0,'resampled':False},ensure_ascii=False,indent=2)+'\n',encoding='utf-8')
print(target)
'@ | & $ActPython -
if ($LASTEXITCODE -ne 0) { throw '公开回合读取失败。' }
```

该 NPZ 保留原始 `episode0_state/action/timestamp/frame_index/global_index`，不是完整历史 `inputs.npz` 的逐字节副本。下一步实际使用其中的 state 和 timestamp；不会读取不存在的历史预测字段。

### B5．生成多位置 teacher，并独立核对保存轨迹

```powershell
& $SimPython 'simulation\generate_multisite_teacher.py' `
```

生成器的完整清单是 **25 train + 4 validation + 11 旧 test/诊断位置**，共 40 条。训练位置为 XY 各 `{-40,-20,0,20,40}` mm 的网格。通过单条基础 teacher 和 IK 偏移生成，不能称作 25 条独立人工示范。`--stage all` 会生成清单中的物理 teacher；其 test 动作不能进入模型训练。生成进程退出码为 0 也不足以证明全成功，必须看 summary 的 passed 数并通过紧随其后的核验。

这里的 11 个旧 test 标签与最终 `position_plan.json` 中 8 个 test 位置不是同一个集合；不要把两种计数混为一谈。

```powershell
if ($LASTEXITCODE -ne 0) { throw '多位置训练未完整结束，保留日志和已有检查点。' }
```

应得到 `training_report.json`、`training_metrics.csv`，以及 `checkpoints/step_001000` 至 `step_005000`。5000 是连续优化器更新次数；一个 batch sample 是某时刻 state、双路 RGB 和本回合接下来 100 行目标动作，不是一个完整回合。每批随机 8 个起点，5000 步共 40,000 个观测窗口；没有显式 epoch 循环。

长训实际采用 FP32、AdamW 全网络统一 LR `1e-5`、weight decay `1e-4`、梯度 norm 上限 10，没有 scheduler、warmup 或梯度累积。源码会在 OOM 时将 batch 减半，因此必须检查报告的 `final_batch_size` 和 `oom_batch_reductions`，不能只按请求值写“batch8”。`--prior-adaptation-steps` 仅是来源步数元数据，不恢复上个阶段的优化器状态。

检查点里保存的 `optimizer_lr/optimizer_lr_backbone` 可能仍是来源配置值；本脚本直接创建 AdamW，判断实际训练参数应看训练入口和 `training_report.json`，不能仅看模型 config。

### B8．先看 loss 和离线 MAE，再做独立物理验证选模

训练 loss 为 `标准化动作 L1 + 10×KL`，padding 排除。离线验证在每回合 `[0,100,201,301,402]` 五个观测锚点做新预测，只给模型 state/wrist/top；之后对有效动作行计算 MAE。它不测接触、夹持和是否入盒。

不能凭训练 loss 最低选权重。历史分支 step5000 最近 100 步训练 loss 均值低于 step3000，但离线验证和物理结果没有随之单调改善。新分支需比较自己的五个保存点与两种执行模式。

原 `run_long5000_validation_20261024.py` 还会加载历史 retained-v1-step600，且 v2 是对已有原矩阵的恢复器；它们**不能在缺少历史候选与运行目录的新副本中直接充当通用一键命令**。公开起点的新分支可明确限定为本分支五个保存点，逐个运行现有评估 CLI：

```powershell
$LongRun = 'runs\mujoco_iteration_20261024\long5000_from_published_v1'
$MatrixRoot = 'runs\public_training_validation_v1'
if (Test-Path -LiteralPath $MatrixRoot) { throw '验证输出已存在，请保留并换一个新名字。' }
foreach ($Step in @(1000,2000,3000,4000,5000)) {
    $Candidate = Join-Path $LongRun ('checkpoints\step_{0:D6}\pretrained_model' -f $Step)
    foreach ($Mode in @('chunk100','ensemble1')) {
        foreach ($Split in @('baseline','validation')) {
            $Destination = Join-Path $MatrixRoot ('step_{0:D6}\{1}\{2}' -f $Step,$Mode,$Split)
            & $SimPython 'simulation\evaluate_feedback_20261024.py' `
              --position-plan 'runs\mujoco_iteration_20261024\position_plan.json' `
              --split $Split --mode $Mode --model-dir $Candidate --output-dir $Destination
            if ($LASTEXITCODE -ne 0) { throw "候选 $Step / $Mode / $Split 中止：保留输出，核对原因后再决定下一步。" }
        }
    }
}
```

这个命令只启动原位与四点 validation，不运行最终八点。每份 `evaluation.json` 需要完整完成；若限位中止或其他错误，不能把部分结果悄悄计作“完整四点失败 0/4”，也不要自动覆盖重跑。

按以下顺序整理每个“权重＋模式”的结果，**不使用最终八点来选择**：

1. 同模式原位任务成功才准入。
2. 四点验证 `successes` 更多者优先。
3. 同分比较 `results[].contacts.physical_grasp_confirmed` 为真的回合数量，即稳态抓持。
4. 再同分才比较训练报告对应 checkpoint 的离线 `normalized_chunk_mae`，低者优先。
5. 仍同分依原规则优先 `chunk100`，再优先更早保存点。

这是新分支五个候选的比较；原历史矩阵还包含 retained-v1，因此候选集合不同。若没有任何候选满足准入，应继续迭代训练/数据并保持最终八点未使用，不强行宣布复现成功。

### B9．冻结选择后才运行最终八点

在读到最终结果前，写下这次选中的模型目录、模式、六文件 SHA、位置计划 SHA 和输入协议 SHA。不要直接照抄历史“step3000＋ensemble1”作为新分支最优答案。

```powershell
$ChosenModel = Read-Host '填写你根据原位和四点验证选定的 pretrained_model 目录'
$ChosenMode = Read-Host '填写本次选定模式：chunk100 或 ensemble1'
if ($ChosenMode -notin @('chunk100','ensemble1')) { throw '模式无效。' }
if (-not (Test-Path -LiteralPath (Join-Path $ChosenModel 'model.safetensors'))) { throw '模型文件不存在。' }
& $SimPython 'simulation\evaluate_feedback_20261024.py' `
  --position-plan 'runs\mujoco_iteration_20261024\position_plan.json' `
  --split test --mode $ChosenMode --model-dir $ChosenModel `
  --output-dir 'runs\public_training_final8_v1'
if ($LASTEXITCODE -ne 0) { throw '最终评估中止，保留完整错误与部分输出。' }
```

最终计划是 8 个位置、每点一次、每回合 15 秒。`chunk100` 每回合 5 次新网络查询；`ensemble1` 每回合 450 次新查询，并对所有覆盖当前时刻的预测按最旧到最新 `exp(-0.01*i)` 加权。两者都是 30 Hz 仿真动作网格；前者视觉查询约 0.3 Hz，后者视觉查询 30 Hz，**都不自动等于墙钟实时运行**。物理内部以 1 ms 子步推进。

结果只支持本任务、固定物体/相机/盒子、训练 XY 范围内的位置变化，即**局部位置泛化**。换物体、换视角、改盒子、遮挡、初态大变动、训练范围外位置，都不由这八次实验自动证明。若看过八点结果后继续按它们调参，这八点应改称开发集，并另设新的留出点。
